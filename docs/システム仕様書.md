## 2. システム概要

本システムは、ブラウザーで指定された棚数、作業員数、フォークリフト数に基づいて、倉庫の2次元グリッドとABC分析による棚割りを生成し、SimPyでピッキング作業を離散事象シミュレーションするアプリケーションである。処理結果として、メイクスパン、作業員・フォークリフトの稼働率と待ち時間、およびグリッドレイアウトを表示する。

現在のStreamlitアプリは動作確認用のサンプルデータを自動生成する。利用者が商品マスター、実オーダー、実倉庫図面をアップロードする機能は含まない。

## 3. 実行環境・起動方法

### 3.1 主要ライブラリ

| ライブラリ | 用途 |
|---|---|
| Python | アプリケーション実行 |
| Streamlit | ブラウザーUI、スライダー、結果表示 |
| SimPy | 離散事象シミュレーションと資源管理 |

依存パッケージはプロジェクトルートの `requirements.txt` に定義する。

### 3.2 起動

プロジェクトルートで以下を実行する。

```powershell
.\venv\Scripts\python.exe -m streamlit run app.py
```

Streamlitが表示するURL（通常 `http://localhost:8501`）をブラウザーで開く。終了時は起動した端末で `Ctrl+C` を押す。

## 5. 機能仕様

### 5.1 入力

アプリのサイドバーで次の値を指定する。

| 項目 | 範囲 | 初期値 | 説明 |
|---|---:|---:|---|
| 棚の数 | 1～1000 | 134 | 商品SKU数および棚割り対象商品の数として扱う |
| 作業員数 | 1～100 | 13 | 同時にオーダーを処理できる作業員リソース数 |
| フォークリフト数 | 0～50 | 4 | 0台は入力可能だが、運搬できないためシミュレーションはエラーを表示して終了する |
| コンテナ数 | 作業員数と同数 | 作業員数に連動 | UIでは個別入力できない。作業員数と同じ数をシミュレーションに渡す |
| 平均荷物重量 | 0.5～100.0 kg | 10.0 kg | 0.5 kg刻み。重量は速度低下、ピッキング・積載時間に反映 |
| 荷物サイズ区分 | 小型・中型・大型 | 中型 | 小型は作業員手持ち、中型はコンテナ、大型はフォークリフトで搬送 |
| 最大同時搬送数 | 1～20個 | 5個 | 1バッチに含める商品個数の上限。超える注文は複数回に分割 |
| 棚配置ルール | ABC優先 / ピッキング頻度優先 | ABC優先 | ABC優先はA/B/Cランク、頻度優先はピッキング頻度で棚を割り当てる |

### 5.2 グリッド・通路・I/Oポイント

- グリッドは50行×50列で固定する。
- 座標は `(行, 列)` で表す。
- 通路は行・列のインデックス5の倍数（5～45）に配置する。
- I/Oポイントはグリッド下辺中央 `(49, 25)` に1か所配置する。
- グリッドセルの意味は次のとおり。

| 表示値 | 意味 |
|---|---|
| `.` | 床 |
| `A` | 通路 |
| `S` | 商品を割り当てた棚セル |
| `I` | 出入口（I/Oポイント） |

棚数は個別の棚の段数・寸法ではなく、1セルにつき1商品SKUを割り当てる棚割り枠数として表現する。棚セル候補は外周を除いた床セルのうち、上下左右いずれかで通路またはI/Oに接する位置から選ぶ。通路に面したセルを予約することで、各棚へ通路から到達できる。候補はI/Oポイントまでのマンハッタン距離が小さい順、その後は行・列順に並べる。

### 5.3 ABC分析と棚割り

1. 商品IDを `SKU-001` から連番で生成する。
2. ピッキング頻度は固定乱数シード `42` のNumPy Zipf分布（パラメーター1.7）で生成する。
3. ABC区分が入力されないため、ピッキング頻度から区分を計算する。頻度降順に並べ、全頻度に対する累積比率が80%未満の範囲をA、80%以上95%未満をB、それ以降をCとする（実装では各商品を加算する前の累積比率で判定）。
4. A、B、Cの順に、さらに区分内ではピッキング頻度の高い順に棚セルへ割り当てる。
5. 棚割り表には商品ID、頻度、ABC区分、行、列、I/Oポイントからの距離を含める。

### 5.4 サンプルオーダーの生成

- オーダー数は `max(20, 棚数 × 2)` とする。
- 各オーダーの商品数は1～4件の範囲で乱数生成する。ただし商品数を棚数より多くしない。
- 商品はピッキング頻度に比例する確率で選び、同一オーダー内で重複させない。
- 商品ごとのピッキング数量は1～3個で生成する。
- 乱数シードが固定されているため、同一の棚数・リソース数に対して同じサンプルシナリオを再現する。

### 5.5 ピッキング処理モデル

各オーダーは次の順に処理する。

1. 作業員リソースを要求する。
2. コンテナリソースを要求する。
3. 作業員はI/Oポイントを出発し、オーダー内の商品を指定順に訪問する。
4. 棚間の移動時間を経過させ、商品数量に応じたピッキング時間を経過させる。
5. 中型・大型ではフォークリフトリソースを要求する。待機中の作業員はオーダーの資源を保持する。
6. フォークリフトは現在位置から最後に訪問した棚へ移動し、I/Oポイントまで搬送する。
7. 作業員はI/Oポイントへ戻る。全バッチ完了後にオーダーを完了し、使用中の資源を解放する。

倉庫グリッド指定時はA*で通路・床・I/Oセルを上下左右に探索し、途中の棚セルを避ける最短経路を使う。移動距離は経路上のグリッド辺数で計算する。通路グリッド未指定のAPI呼び出しでは行・列順のマンハッタン経路を使う。既定値は作業員速度1セル/時間単位、フォークリフト速度2セル/時間単位、ピッキング時間1時間単位/個である。時間単位はモデル上の任意単位であり、現実の時間に換算する場合は速度・作業時間の入力値を調整する必要がある。

荷物条件の扱いは次のとおり。

- 小型: コンテナとフォークリフトを使わず、作業員が各搬送バッチをI/Oへ手持ちで戻す。
- 中型: 各バッチでコンテナを確保し、フォークリフトでI/Oへ運ぶ。
- 大型: フォークリフトで搬送する。大型はコンテナ資源を要求しない。
- 1オーダーの数量を最大同時搬送数以下のバッチに分割し、バッチごとに棚を巡回して搬送する。
- 重量による速度倍率は、作業員が基準速度を `1 + 重量kg / 50` で割る。フォークリフトはサイズ倍率適用後の基準速度を `1 + 重量kg / 200` で割る。
- サイズによる速度倍率は、作業員が小型/中型/大型で `1.0 / 1.0 / 0.9`、フォークリフトが `1.0 / 1.0 / 0.8`。
- ピッキング倍率は小型/中型/大型で `1.0 / 1.0 / 1.25` とし、さらに `1 + 重量kg / 100` を掛ける。フォークリフトの積載時間として、各搬送バッチに `個数 × 基準ピッキング時間 × 重量kg / 100` を加算する。
- 中型・大型ではフォークリフトが1台以上必要。小型はフォークリフト0台でもシミュレーションできる。

### 5.6 表示する結果

メイン画面は以下の3タブで構成する。サイドバーには棚数、作業員数、フォークリフト数を基本条件として表示し、棚配置ルール、運搬物条件、最適化の制約・コストは初期状態で閉じた「詳細な詳細設定・運搬物パラメータ」エキスパンダーにまとめる。

| タブ | 主な内容 |
|---|---|
| 倉庫レイアウト・3Dモデル | 2Dグリッドと操作可能な3Dモデル、棚割り・完了時間の折りたたみ表 |
| リアルタイム・アニメーション | 時刻スライダー、再生ボタン、エージェント位置、時点別KPI |
| 最適化・KPI分析 | 探索条件、最適化実行、推奨条件、感度分析グラフ、候補一覧 |

主要KPIはタブの上部に横並びで表示する。平均稼働率は作業員とフォークリフトの稼働率の算術平均とし、フォークリフト0台の場合は作業員稼働率のみを表示する。総待ち時間は作業員・フォークリフト・コンテナ各待ち時間の合計とする。

| 結果 | 定義・表示 |
|---|---|
| メイクスパン | 全オーダーのシミュレーション完了時刻 |
| 作業員稼働率 | 全作業員の移動・ピッキング実作業時間 ÷（メイクスパン × 作業員数） |
| フォークリフト稼働率 | フォークリフトの空車移動・搬送・積載時間 ÷（メイクスパン × フォークリフト数） |
| 作業員待ち時間 | 作業員リソースの取得待ち時間の合計 |
| フォークリフト待ち時間 | フォークリフトリソースの取得待ち時間の合計 |
| コンテナ待ち時間 | コンテナリソースの取得待ち時間の合計 |
| フォークリフト走行距離 | シミュレーション中の空車・積載移動のマンハッタン距離合計 |
| フォークリフト稼働時間 | 空車移動・積載移動・荷役の実作業時間合計 |
| 処理アイテム数 | オーダーの全ピッキング数量 |
| グリッドレイアウト | 選択時刻の作業員・フォークリフト位置を重ねた2D図、操作可能な3D図を表示 |
| 棚割り表 | 商品、頻度、ABC区分、棚座標、I/O距離の先頭20件 |
| オーダー完了表 | オーダーIDと完了時刻の先頭20件 |

シミュレーションAPIは各待ち時間の平均値も返すが、画面の集計KPIでは合計値を表示する。シミュレーション再生タブの時刻スライダーは時系列ログから直前のエージェント状態を選択し、稼働作業員数、累積待ち時間、完了オーダー数を更新する。アニメーション再生は表示フレーム数を最大40程度に間引く。

グリッド図の凡例では床/空き領域を薄いグレー、通路をグレー、I/Oを赤、A/B/C商品棚を濃青/青/水色で表示する。ABC情報がない棚セルは青で表示する。

3D図は列をX、行をY、棚高をZとして、暗色コンクリート風グリッド床面、通路帯、立体的なI/Oドック、複数段の棚板と金属フレームからなるラックを表示する。棚板はAランクを赤、Bランクを黄、Cランクを緑で色分けし、ランクが不明な棚は青で表示する。時刻スライダーで選択したエージェント位置も3Dマーカーとして表示する。Plotlyの3Dシーンはマウス操作による回転・ズーム・平行移動に対応する。

### 5.7 時系列トレース・アニメーション

- シミュレーションは既定で1時間単位ごと、およびエージェント状態変化時に作業員・フォークリフトの位置と状態を記録する。
- 記録間隔は詳細設定で0.25 / 0.5 / 1.0モデル時間単位から選択でき、既定値は0.5。短い間隔ほど位置ログが細かくなる一方、ログ量とシミュレーション処理時間が増える。
- トレース列は `time`, `agent_id`, `agent_type`, `x`, `y`, `state`, `wait_time_total`, `queue_count`, `completed_order_count`。座標は列をX、行をYとする。
- 状態は `moving`、`picking`、`waiting`。移動中はマンハッタン経路に沿った座標を時間間隔ごとに補間する。
- 待ち時間は完了済みの待ち時間と、記録時点で継続中のリソース待ち時間の合計である。
- アニメーションはPlotlyのブラウザー内3Dフレーム、再生・一時停止ボタン、時間スライダーで操作する。暗色床、立体棚、I/Oドックを背景に、作業員は青い円、フォークリフトはオレンジの四角で表示し、記録位置間は線形補間する。各エージェントの直近8サンプルを薄い軌跡線として表示する。
- カメラは斜め俯瞰 `(1.5, 1.5, 1.2)`、真上 `(0, 0, 2.5)`、正面 `(0, -2.5, 0.5)` の3視点から切り替える。
- アニメーション上部のKPI表示は各フレームに含まれ、稼働作業員数、累積待ち時間、リソース取得待ち要求数（渋滞指標）、完了オーダー数を再生位置に同期する。ブラウザー内再生中のKPI更新はPlotlyチャート内で行う。
- フレームレートは12 / 20 / 30 FPS、再生速度は0.5x / 1.0x / 2.0x / 5.0x、最大表示フレーム数は30～240で調整する。再生速度はPlotlyフレームの再生間隔に反映する。フレーム上限を超える長いログは時刻全体から均等に間引いて表示し、全件ログはシミュレーション結果に保持する。
- アニメーションフレームは移動するエージェントと軌跡のトレースのみを更新し、静的な倉庫モデルは再描画しないことで表示負荷を抑える。

### 5.8 最適条件探索

- サイドバーで最適化モード、目標メイクスパン、コスト予算、作業員・フォークリフト探索上限、各リソースの時間単価、バランスモードの最低稼働率、エコモードの排出係数を指定する。
- 探索対象は作業員1～上限、必要最小数～フォークリフト上限、および `abc` / `frequency` の2棚配置ルール。最大500構成を超える指定は計算を拒否する。
- 各候補は同一の商品・注文データ、荷物条件を使ってSimPyで評価する。
- 目的関数は4モードを備える。
  - 時間優先: メイクスパン最小。同時間の場合は推定費用が低い候補を選ぶ。
  - コスト最小化: 目標時間と任意の予算を満たす候補から推定費用を最小化。作業員費用は全作業員のメイクスパン、フォークリフト費用は実測した稼働時間を基に算出する。
  - バランス優先: 作業員・使用中のフォークリフトの最低稼働率を満たす候補から、1アイテムあたり推定費用を最小化する。該当候補がなければ、稼働率不足が最小の候補を提示する。
  - 環境・エコ優先: `フォークリフト走行距離 × グリッドあたり係数 + フォークリフト稼働時間 × 時間あたり係数` のCO2換算推定値を最小化する。係数は利用者が設定する仮定値であり、認証済み排出量ではない。
- 時間・コスト・稼働率制約が実現不可能な場合は、制約未達を明示し目的に近い候補をフォールバックとして提示する。
- Plotlyの感度分析グラフ、候補KPI表、現在条件と推奨条件の比較表を表示する。推薦条件の適用ボタンは作業員数、フォークリフト数、棚配置ルールの入力欄を更新する。
- 結果は設定された探索上限・単価・単一のサンプル注文に基づく比較値であり、実際の人件費計算や設備投資判断を代替しない。

## 6. 非機能・運用仕様

- 同一の入力条件に対するサンプルシナリオを再利用するため、`run_scenario` の結果をStreamlitのデータキャッシュに保存する。
- 入力変更により関数引数が変わると、その入力条件でシナリオを再計算する。
- 現行アプリはローカルでの単一プロセス起動を想定する。認証、権限管理、データベース保存、複数ユーザーの結果管理は提供しない。
- アプリは商品数・オーダーを画面内で生成し、入力ファイルや外部システムとは連携しない。

## 7. 制約・モデル上の前提

- 棚位置は自動配置したグリッドセルであり、棚の実寸、棚段、通路幅、片側通行はモデル化しない。
- Streamlitと最適化から呼び出すシミュレーションにはグリッドを渡し、A*で床・通路・I/Oセルを上下左右に探索する。棚セルは到着先としてのみ進入を許可し、経路途中の通過を禁止する。棚は通路に接するセルへ割り当て、到達性を保つ。通路グリッドを省略したAPI呼び出しは行・列順のマンハッタン経路を使う。
- 移動は選択したグリッド経路の辺ごとに補間して記録する。混雑による速度低下、通路幅、旋回半径、複数エージェントの衝突・譲り合いはモデル化しない。
- 作業員は各オーダーの開始時にI/Oポイントにいるものとして計算し、オーダー間の移動は含めない。
- フォークリフトの移動は前回の配送後の位置から棚への空車移動、および棚からI/Oへの積載移動を含む。待機場所、充電、故障は含めない。
- フォークリフト待ちの間も作業員とコンテナはオーダー完了まで占有される。
- フォークリフト稼働率は空車移動、積載移動、荷役時間を含む。作業員稼働率は棚への移動、ピッキング、I/Oへの戻り時間を含む。
- 棚数はSKU数として扱うため、「物理的な棚本体の数」とは区別する。
- 結果は設定した簡略モデルの比較・学習用であり、実運用の人員配置や投資判断に使う場合は、実測データに基づく時間分布・経路・設備条件の追加が必要である。

## 8. テスト仕様

ユニットテストはプロジェクトルートで実行する。

```powershell
$env:PYTHONPATH = Join-Path (Get-Location) 'src'
.\venv\Scripts\python.exe -m unittest discover -s tests -v
```

テスト対象はグリッドとI/O配置、ABC棚割り、入力値検証、メイクスパン・稼働率計算、走行距離・処理数量、トレース、2D/3Dアニメーション、4種類の最適化目的と制約フォールバックである。
