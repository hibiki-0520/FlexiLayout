## 2. システム概要

本システムは、ブラウザーで指定された棚数、作業員数、フォークリフト数に基づいて、倉庫の2次元グリッドとABC分析による棚割りを生成し、SimPyでピッキング作業を離散事象シミュレーションするアプリケーションである。処理結果として、メイクスパン、作業員・フォークリフトの稼働率と待ち時間、およびグリッドレイアウトを表示する。

現在のStreamlitアプリは動作確認用のサンプルデータを自動生成する。利用者が商品マスター、実オーダー、実倉庫図面をアップロードする機能は含まない。

## 3. 実行環境・起動方法

### 3.1 主要ライブラリ

| ライブラリ | 用途 |
|---|---|
| Python | アプリケーション実行 |
| Streamlit | ブラウザーUI、スライダー、結果表示 |
| SimPy | 離散事象シミュレーションと資源管理 |
| NumPy | グリッド、乱数によるサンプルデータ生成 |
| pandas | 商品棚割り表、結果表 |
| Matplotlib | グリッドレイアウトの描画 |

依存パッケージはプロジェクトルートの `requirements.txt` に定義する。

### 3.2 起動

プロジェクトルートで以下を実行する。

```powershell
.\venv\Scripts\python.exe -m streamlit run app.py
```

Streamlitが表示するURL（通常 `http://localhost:8501`）をブラウザーで開く。終了時は起動した端末で `Ctrl+C` を押す。

## 5. 機能仕様

### 5.1 入力

アプリのサイドバーで次の値を指定する。

| 項目 | 範囲 | 初期値 | 説明 |
|---|---:|---:|---|
| 棚の数 | 1～200 | 50 | 商品SKU数および棚割り対象商品の数として扱う |
| 作業員数 | 1～20 | 4 | 同時にオーダーを処理できる作業員リソース数 |
| フォークリフト数 | 1～10 | 2 | 同時にコンテナを運搬できるフォークリフトリソース数 |
| コンテナ数 | 作業員数と同数 | 作業員数に連動 | UIでは個別入力できない。作業員数と同じ数をシミュレーションに渡す |

### 5.2 グリッド・通路・I/Oポイント

- グリッドは50行×50列で固定する。
- 座標は `(行, 列)` で表す。
- 通路は行・列のインデックス8、16、24、32、40に配置する。
- I/Oポイントはグリッド下辺中央 `(49, 25)` に1か所配置する。
- グリッドセルの意味は次のとおり。

| 表示値 | 意味 |
|---|---|
| `.` | 床 |
| `A` | 通路 |
| `S` | 商品を割り当てた棚セル |
| `I` | 出入口（I/Oポイント） |

棚数は個別の棚の段数・寸法ではなく、1セルにつき1商品SKUを割り当てる棚割り枠数として表現する。棚セル候補は、外周を除いた範囲にある床セルから選ぶ。棚セル候補はI/Oポイントまでのマンハッタン距離が小さい順、その後は行・列順に並べる。

### 5.3 ABC分析と棚割り

1. 商品IDを `SKU-001` から連番で生成する。
2. ピッキング頻度は固定乱数シード `42` のNumPy Zipf分布（パラメーター1.7）で生成する。
3. ABC区分が入力されないため、ピッキング頻度から区分を計算する。頻度降順に並べ、全頻度に対する累積比率が80%未満の範囲をA、80%以上95%未満をB、それ以降をCとする（実装では各商品を加算する前の累積比率で判定）。
4. A、B、Cの順に、さらに区分内ではピッキング頻度の高い順に棚セルへ割り当てる。
5. 棚割り表には商品ID、頻度、ABC区分、行、列、I/Oポイントからの距離を含める。

### 5.4 サンプルオーダーの生成

- オーダー数は `max(20, 棚数 × 2)` とする。
- 各オーダーの商品数は1～4件の範囲で乱数生成する。ただし商品数を棚数より多くしない。
- 商品はピッキング頻度に比例する確率で選び、同一オーダー内で重複させない。
- 商品ごとのピッキング数量は1～3個で生成する。
- 乱数シードが固定されているため、同一の棚数・リソース数に対して同じサンプルシナリオを再現する。

### 5.5 ピッキング処理モデル

各オーダーは次の順に処理する。

1. 作業員リソースを要求する。
2. コンテナリソースを要求する。
3. 作業員はI/Oポイントを出発し、オーダー内の商品を指定順に訪問する。
4. 棚間の移動時間を経過させ、商品数量に応じたピッキング時間を経過させる。
5. ピッキング後にフォークリフトリソースを要求する。
6. フォークリフトが最後に訪問した棚からI/Oポイントまでコンテナを運ぶ。
7. 運搬終了後にオーダー完了とし、作業員・コンテナの占有を解放する。

移動距離は行・列の差の絶対値の和（マンハッタン距離）で計算する。既定値は作業員速度1セル/時間単位、フォークリフト速度2セル/時間単位、ピッキング時間1時間単位/個である。時間単位はモデル上の任意単位であり、現実の時間に換算する場合は速度・作業時間の入力値を調整する必要がある。

### 5.6 表示する結果

| 結果 | 定義・表示 |
|---|---|
| メイクスパン | 全オーダーのシミュレーション完了時刻 |
| 作業員稼働率 | 全作業員の移動・ピッキング実作業時間 ÷（メイクスパン × 作業員数） |
| フォークリフト稼働率 | 全フォークリフトの運搬実作業時間 ÷（メイクスパン × フォークリフト数） |
| 作業員待ち時間 | 作業員リソースの取得待ち時間の合計 |
| フォークリフト待ち時間 | フォークリフトリソースの取得待ち時間の合計 |
| コンテナ待ち時間 | コンテナリソースの取得待ち時間の合計 |
| グリッドレイアウト | 床・通路・棚・I/Oを色分けした50×50図。棚割り情報がある場合、棚はABC区分別に表示 |
| 棚割り表 | 商品、頻度、ABC区分、棚座標、I/O距離の先頭20件 |
| オーダー完了表 | オーダーIDと完了時刻の先頭20件 |

シミュレーションAPIは各待ち時間の平均値も返すが、現行の画面では合計値のみを表示する。

グリッド図の凡例では床/空き領域を薄いグレー、通路をグレー、I/Oを赤、A/B/C商品棚を濃青/青/水色で表示する。ABC情報がない棚セルは青で表示する。

## 6. 非機能・運用仕様

- 同一の入力条件に対するサンプルシナリオを再利用するため、`run_scenario` の結果をStreamlitのデータキャッシュに保存する。
- 入力変更により関数引数が変わると、その入力条件でシナリオを再計算する。
- 現行アプリはローカルでの単一プロセス起動を想定する。認証、権限管理、データベース保存、複数ユーザーの結果管理は提供しない。
- アプリは商品数・オーダーを画面内で生成し、入力ファイルや外部システムとは連携しない。

## 7. 制約・モデル上の前提

- 棚位置は自動配置したグリッドセルであり、棚の実寸、棚段、通路幅、障害物、片側通行はモデル化しない。
- 移動時間はマンハッタン距離による単純計算であり、実際の通路ネットワークに沿った経路探索や混雑による速度低下はない。
- 作業員は各オーダーの開始時にI/Oポイントにいるものとして計算し、オーダー間の移動は含めない。
- フォークリフトの移動は最後の商品棚からI/Oポイントへの片道運搬のみ。フォークリフトの棚への往路、待機場所、充電、故障、荷役時間は含めない。
- フォークリフト待ちの間も作業員とコンテナはオーダー完了まで占有される。
- フォークリフト稼働率はコンテナ運搬時間のみで算出する。作業員稼働率は棚への移動時間とピッキング時間を含む。
- 棚数はSKU数として扱うため、「物理的な棚本体の数」とは区別する。
- 結果は設定した簡略モデルの比較・学習用であり、実運用の人員配置や投資判断に使う場合は、実測データに基づく時間分布・経路・設備条件の追加が必要である。

## 8. テスト仕様

ユニットテストはプロジェクトルートで実行する。

```powershell
$env:PYTHONPATH = Join-Path (Get-Location) 'src'
.\venv\Scripts\python.exe -m unittest discover -s tests -v
```

テスト対象はグリッドとI/O配置、ABC棚割り、入力値検証、メイクスパン・稼働率計算、フォークリフト待ちの発生である。

## 9. 将来拡張候補

以下は現行機能には含まれない拡張候補である。

- 実商品マスター・オーダーCSVのアップロード
- コンテナ数、速度、ピッキング時間、グリッド寸法のUI設定
- 通路ネットワークを考慮した最短経路と動線描画
- 棚の物理寸法、複数段、障害物、通行制限のモデル化
- オーダー別・時間帯別の詳細ログ、結果のCSV出力
- 複数回試行によるばらつき・信頼区間の評価
